# 验证与完成判定

静态检查、依赖溯源、渲染、真实操作、视觉和业务回归分开。测试脚本、截图和报告放在独立任务示例目录，不污染原始业务页面。无需为纯文字调整累积镜像测试；优先覆盖真实风险。

## 静态及复用检查

check_page.py 检查本地资源可达、重复属性和显式标签、页面 provenance、库版本、打包运行资产哈希及本地 JS 语法（若有 Node）。它不能判断业务完整、实际DOM状态、CSS视觉一致或页面是否有恶意业务代码，也不能证明所有CSS都遵循规范。修改原应用没有本工具provenance时，应按项目检查方式人工登记复用，不为了通过检查重建原页面。

普通生成应检查变量引用与局部样式，适用的长文本、空/无匹配、加载、错误、只读、禁用及取消保护。固定示例数据要明确范围。

## 管理页面关键路径

组合筛选 → 排序 → 分页 → 选择范围；新增/编辑校验和回填；取消/关闭保护；删除默认取消及具体对象；导出存在真实文件且范围一致。正式开发还需验证实际权限、接口失败和幂等。

## AI 页面关键路径

空白禁发 → 发送生成 → 停止保留草稿 → 原轮重试；失败就地恢复；会话草稿隔离；结果版本与工作区收放不丢失。涉及教师关联时，验证选择不发送、发送数据保留资源/技能/Agent、运行锁定、原轮重试和会话隔离。工作区默认插槽为空且无擅加业务动作；需求指定内容时，验证业务内容挂载、收放保留状态与相应关键流程。检查组件卸载后过期回调不写回。不把模拟通过写成模型或后台通过。

## 浏览器与视觉

遵守当前环境的浏览器工具与项目授权。可运行时检查目标PC视口、局部滚动、焦点、浮层、输入与操作的可达性；若当前任务明确需要移动端，再扩大范围。file协议不支持时用正常本地HTTP预览，不能绕过工具策略；明确未实测的打开方式。

## 完成输出

页面入口、版本/来源、复用组件、扩展、已通过/未执行检查、实际服务或模拟边界。任何检查失败需修复或说明影响，不能把仅静态通过写为整体可用。
