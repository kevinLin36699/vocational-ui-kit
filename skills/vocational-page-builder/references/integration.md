# 业务、整改与兼容性

## 业务规则不能从组件样例推定

执行时重新读取目标项目的 AGENTS.md、共同规则、对应角色的当前专项和相关控制器。保留对象与版本、事件处理、权限、自动/手动保存、归档、作业考试限制及源状态。视觉依组件库，业务按本次要求和当前有效约定。

创建技能时已经观察到：源平台教师专项增加“保存课程包为主路径、分发可选、章节绑定已保存版本”，而组件库 v1.0.0 的工作区演示仍以分发按钮作主动作。此例说明必须重读当前业务，**不能把本段当作今后永远不变的业务规则或硬编码动作名称**。处理时记录外观复用与业务适配，不擅自修改组件库。

## 不直接全局覆盖

库的 components.css 带 body、button、input 等基础 reset，voc-ui.js 含 document 事件委托。整改既有应用时先隔离或限定作用域；不要把它们全局加载后期待无关页面、PPT/视频/图谱、考试正文都保持原行为。优先在副本、受控容器或项目组件适配层实现。

局部修改定位相应 DOM/控制器，保留有效 ID 与节点绑定；不能为了视觉一致重建正在运行的播放器、输入草稿或任务。跨角色共用组件变动需核对实际影响，不能只测一个角色。

## 框架项目

沿目标框架的状态、组件和构建方式封装。使用其生命周期销毁定时器、订阅和浮层；可参考库实现，但不要同时让框架与原生示例控制器拥有同一份数据或 DOM。只有用户要求演示时可保留固定数据配方。没有明确生产接口时标记缺口，不捏造服务已接通。

## 迁移记录

记录旧选择器/页面 → 新组件 → 参数/数据适配 → 业务例外 → 验证范围。库中的词法映射仅是候选，不是已完成的迁移或安全替换脚本。改变样式不等于已经通过权限、计分或版本回归。
