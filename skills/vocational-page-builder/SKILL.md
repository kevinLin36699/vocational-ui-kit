# 高职教平台页面生成与整改

把用户的业务需求落实为符合指定版本组件库的可运行页面。支持新建、整改和局部修改；保留任务范围、业务含义和必要交互。

## 先解析组件库，按需读取

技能根目录以下文 `SKILL_ROOT` 表示。先运行：

```bash
python3 "$SKILL_ROOT/scripts/resolve_library.py"
```

绑定路径只维护在 [references/library-binding.json](references/library-binding.json)，不从聊天记忆推定路径。显式 `--library-root`、环境变量 `VOCATIONAL_UI_LIBRARY_ROOT`、当前项目 `.vocational-page-builder.json` 中的 `library_root` 可覆盖默认；指定版本用 `--version`。解析器报告实际路径、版本、文档和源文件哈希，兼容版本更新提示重新读取变化文件；主版本不兼容或指定版本不符时不静默降级。

每次先读取解析结果中的 **generation_standard、standard、api、limitations**，再按任务查组件与模板：

```bash
python3 "$SKILL_ROOT/scripts/resolve_library.py" --component table --component form --pattern list
```

只加载所选组件的规范、参数和源码，不默认读取整份迁移索引或全部业务代码。业务演示从解析结果的 `examples` 按需打开；示例数据仅在明确演示任务中使用，不自动复制进真实业务页。查阅导航见 [references/library-map.md](references/library-map.md)。绑定失败时先完成不依赖标准的分析，指出所缺材料；不能自造组件 API、替换成另一套通用后台或宣称已完成页面。

## 需求与冲突判断

- 从上下文提取角色、对象、字段、操作、状态、入口、输出位置、技术形式和目标视口；只询问影响核心结果且无法推断的缺口，其余直接推进。
- 视觉与通用交互优先级：本次用户明确要求 → 指定版本组件库 → 组件库示例 → 旧页面样式 → 补充设计。截图仅为业务参考时保留结构、采用组件库视觉；明确像素复刻冲突时按本次要求实施并记录偏离。
- **业务规则与外观分开**：整改前读取适用 `AGENTS.md`、当前角色规则及控制器，保留最新权限、草稿、版本、保存、审核、分发和考试规则。组件库配方中的旧业务示例不能覆盖当前业务约定；参见 [references/integration.md](references/integration.md)。
- 不需要每次访问 AI-base 线上平台，蓝白主题和研究成果以已绑定组件库为准。

## 实现

1. 确定新建、整改或局部修改，选择页面模式。复杂页面简记 CON01～05：身份与入口、结构与滚动、数据与状态、动作与留存、例外与证据。将需求映射到真实组件标识。
2. 检查目标技术栈。HTML 项目复用现有 HTML/CSS/JS；框架项目保留架构并建立适配。仅在用户要求单文件时内联打包，不为套用本技能引入新框架。
3. 复用组件源码、模板和设计变量。参数只用索引及当前 API 真正支持的字段。当前 `table` 支持 `rows/columns/rowKey`，`form` 支持 `fields/values`；先读解析结果的 `controls`、`table_form` 和所选组件参数，再绑定 `VocDataTable` / `VocForm` 实例方法。三批高职教业务组件使用各自的目录、记录、身份和明确回执；需要联动时按 `education_platform` 建立显式桥接。`chat` 仍不支持任意 `messages` 或真实流式接口，`workspace` 默认只提供空插槽；不要把任意 `onSave` 等回调当成通用参数。
4. 补齐请求范围内的可执行交互、校验、状态反馈与恢复。用户要求实际开发时接入真实架构和服务，不用演示数据替代。演示任务明确数据与模拟边界，不把本地保存称为真实入库。
5. 修改已有页面优先局部改动，保留对象 ID、事件、权限、播放器与编辑器状态。不能直接全局引入库的 reset 覆盖原平台或生成作品主题。

新建独立 HTML 页面可使用以下辅助工具，它只建立组件依赖和可运行的模板种子；后续仍需完成具体需求：

```bash
python3 "$SKILL_ROOT/scripts/scaffold_page.py" --output /absolute/new-page --pattern list --title "课程管理"
```

脚本拒绝覆盖已有页面，复制所需运行资产并记录来源版本及哈希；不把组件库全文复制进技能。单文件交付方式和复用边界见 [references/generation.md](references/generation.md)。

## 扩展与 AI

缺少组件时先查变体、再组合；确需局部扩展时沿现有变量与交互原则实现，记录原因、状态、API 和建议回收范围。未经本次授权不改组件库公共标准；只有关键缺口阻碍任务时才暂停，其他工作继续。

**生成内容区只复用通用容器与空插槽**，默认不填入教学大纲、PPT、试题等示例编辑器，不自动添加保存、审核、发布等业务按钮。用户提供具体业务需求时，在该容器内接入对应内容、编辑器及流程；未明确的业务内容继续留空，不能把“只预留容器”理解为忽略已经要求实现的业务。

AI 页面按需读取绑定库的 AI 文档及 [references/ai-pages.md](references/ai-pages.md)。关注预填不自动发送、输入法、停止与重试、原轮恢复、会话草稿隔离、独立结果与工作区、来源真实性和卸载回调失效。模拟要能结束、停止或恢复；不编造真实工具能力、来源或私有推理。作业/考试等限制由当前业务控制，不能被共享输入组件绕过。

当前输入规范：资源入口显示「＋ 资源」，技能入口显示「技能」，分别沿用库中的浅蓝／浅蓝紫样式；资源由 / 或资源菜单唤起，先类型再对象；技能标签在所有正文前且可移除。教师场景按业务配置产业、就业、政策、技术等 Agent 多选项，不显示“教学关联”标题；选择不发送，主动发送携带本轮选择，运行时锁定，重试沿用原轮快照。不要把这些教师选项强制加入其他角色或复制演示 Agent ID 作为真实服务。按需读取解析器返回的 teaching_agents、资源、技能及工作区规范。

详细处理记录目前仅是独立预览示例，不是已替换的公共 process API；仅在任务需要时参考，复用变量建立局部适配，保留真实来源和模拟标识。

## 验证与交付

遵循 [references/verification.md](references/verification.md) 核对组件复用和关键业务行为。新建独立页面可运行：

```bash
python3 "$SKILL_ROOT/scripts/check_page.py" /absolute/new-page/index.html
```

这只验证本地资源、依赖哈希、版本与结构，不代表交互或视觉已通过。按任务授权及环境做浏览器检查；截图/源码测试不替代关键操作，未执行的项目明确标记。原项目不允许默认浏览器自测时遵守其约定，用户明确要求的本次验收按授权范围执行。

交付入口和文件、绑定版本、复用组件、局部扩展、已验证/未覆盖项以及实际数据或模拟边界。只完成已授权页面；不擅自发布、发送真实业务消息或扩大权限。任务数据和偏好不写入技能的公共规则。
